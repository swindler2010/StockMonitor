# Советы по развитию — первый этап задачи №49 / G06

Открытие в 0.16 TEST: **Справка → Советы по развитию**.

В окне два отдельных раздела:

1. **Развитие программы** — ожидание расчётов, возраст результатов, проблемы свечей, ожидание источника и полнота диагностики.
2. **Развитие торговли** — свежесть цены, причины ожидания покупки, проверка входов, размера покупки и выходов в существующих V1/V2.

Советы пронумерованы отдельно: 1.1, 1.2… и 2.1, 2.2… В каждом есть важность, «Что замечено», «Что улучшить» и «Как проверить пользу». Номер означает положение в текущем снимке, а не постоянный ID задачи MASTER.

Первый этап использует локальные правила по сохранённой диагностике. Внешняя ИИ-модель не вызывается, оплачиваемые запросы не выполняются. Нет автоматических правок кода, свечей, торговой стратегии или разрешений. Улучшения торговли сначала проверяются на истории и в теневых портфелях; включение требует решения владельца.

Данные читаются в существующей фоновой очереди при открытии окна и раз в минуту, пока оно открыто. Отдельной системы загрузки, потоков по каждой акции и повторного аудита свечей нет. В основном SQLite используется согласованное чтение; из отдельного теневого журнала читаются только два счётчика завершённых сделок, без балансов, позиций и сумм.

Снимок ограничен: до 512 оценок, 512 запросов переоценки, 2048 проверок качества, 2048 заданий сверки и 512 результатов демоторговли. Записи больше 4 млн символов и повреждённый JSON явно учитываются как непрочитанные. Неполное покрытие показывается в начале текста. Старый статус CURRENT не переопределяет истёкший срок оценки; сохранённые проблемные ряды могут включать резервные данные и не равны числу заблокированных акций. WAIT без BUY и ожидание ограничения API сами по себе не ошибки. Эта панель не предоставляет торговый допуск.

**Копировать для Work** копирует оба раздела; **Сохранить текст…** сохраняет тот же текст в UTF-8. Экспорт не содержит API-ключей, произвольных сообщений поставщиков, путей к данным, позиций или остатков счёта. Автоматической отправки нет.

Проверки: `python -m unittest test_development_advisor`. Они проверяют сроки, причины ожидания, неизвестные данные, раздельную нумерацию, чтение без записи и состав экспорта.

Откат: убрать два добавленных элемента интеграции из `desktop014.py` (импорт панели и пункт меню), затем обычный перезапуск TEST. Новые модули после этого не вызываются. Восстановление старой SQLite, счёта или свечей не требуется. Другие изменения в `desktop014.py` сохраняются.
