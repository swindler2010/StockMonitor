# Проверка программы и скорости Stock Monitor 0.16 TEST

20.11.2026. Статус: **PARTIAL — шесть подтверждённых причин лишней нагрузки исправлены; все возможные ошибки программы не объявляются устранёнными.**

## Что исправлено

1. **Опрос качества на интерфейсе.** Каждую секунду Tk декодировал большой исторический DQ и строил его строку. Теперь используются существующие семантические input_revisions и небольшой кэш identity. Реальное изменение DQ, identity, использованных свечей или минуты по-прежнему вызывает обновление; служебные отметки не создают тяжёлый повторный расчёт.
2. **Чтение после загрузки.** `prepare_feed` теперь работает через существующий `calculate_consistent`: один query-only WAL-снимок, затем окончательная проверка живых ревизий. Удалена недостижимая дублирующая ветка маршрутизации. Действительно изменившиеся входы всё ещё отклоняются.
3. **Диагностика свежести при непрерывном feed.** Раньше следующее обновление могло отменить готовый общий отчёт и немедленно запустить ещё один. Теперь публикуется снимок со своим временем и признаком новых ожидающих входов; автоматические повторы объединяются и ограничены 60 секундами после завершения. Явный запрос панели выполняется без этого ожидания. Изменившийся список инструментов отвергает прежний результат; ошибка остаётся UNAVAILABLE, без вымышленных нулей. Это диагностический отчёт, не продление торгового допуска.
4. **Повторные проверки происхождения свечей.** При одном построении Apple 15m одни и те же квитанции многократно проверялись при загрузке дочерних рядов. Результат проверки повторно используется только внутри того же неизменяемого WAL-чтения. Следующее чтение проверяет квитанции заново; обычный writer этим повторным использованием не пользуется. Добавлены явные зависимости instrument и сохранённой listing proof 15m. Проверка ревизий непосредственно перед публикацией сохранена.
5. **Лишняя загрузка до появления окна.** `_load_cached` больше не материализует архивы всех акций на Tk. Рабочие графики/CORE используют существующие фоновые чтения SQLite. Старый буфер уведомлений наполняется штатным `apply_feed` после проверки результата; уже полученные буферы сохраняются. История с диска не удалена.
6. **Копирование большого дерева доказательств при проверке чисел.** Профиль Apple 1H выявил 18 вызовов `gettex_first.bound`, в которых обычное чтение столбцов вызывало повторные pandas-deepcopy метаданных. Проверяются те же OHLCV/индекс/source через числовое представление без attrs; исходный контракт и identity проверяются по оригинальным метаданным. Никакие доказательства не удаляются. Нули объёма сохраняются; отрицательный объём, невозможный high/low, NaN, нулевая цена, другой источник/валюта/ISIN по-прежнему отклоняются.

Существующая защита от повторной вставки одинакового текста диагностики уже была реализована и не переписывалась. Действующие пакетная отрисовка и Volume Profile сохранены. Кэши, журналы, архивы и модули не удалялись по одному названию или возрасту.
