# Безопасная очистка папки Stock Monitor — 25.11.2026

Проверена папка «СМ», включая действующую 0.16, среду запуска, Review, установочные пакеты и резервные копии. Исходная инвентаризация: примерно 13,826 GiB. Это логический объём файлов; работающая программа продолжает изменять данные, поэтому фактическое изменение свободного места на диске отдельно не измерялось.

## Результат

Первоначально подтверждены **13 672 кандидата**, 762 614 766 байт. Work1 непосредственно удалил **13 671 файл / 762 535 123 байта** — примерно **763 МБ / 727,21 MiB**. Удалены также 730 ставших пустыми каталогов только в пределах этого списка.

| Что удалено | Файлов | Байт |
| --- | ---: | ---: |
| Распакованные старые Review 0.17.0-review.1–5 | 13 414 | 691 734 879 |
| Их метаданные, сохранённые в архиве | 5 | 2 421 208 |
| Точная дополнительная копия установщика Review 7 | 1 | 63 255 587 |
| Старые изолированные тестовые базы test-tmp | 5 | 671 744 |
| Воспроизводимый байткод тестов с сохранёнными исходниками | 246 | 4 451 705 |
| **Всего** | **13 671** | **762 535 123** |

Остался **1 кандидат**: байткод теста диагностики, пересозданный параллельной работой после инвентаризации. Изменившийся файл сознательно пропущен. Неопределённые и действующие материалы не объявлялись ненужными.

Количество программных или свечных ошибок этим этапом не измерялось. Прямых исправлений свечей, сделок и изменений торговой логики Work1 — **0**. Автономная работа CandlePilot в число личных исправлений не включена.

## Что сохранено

- Действующая 0.16, исходники, локальная история Git, настройки, позиции, рисунки, журналы и данные счёта.
- Текущая Review 7 и предыдущая Review 6 для отката; current.json не изменён.
- Основной установщик Review 7, исходные пакеты старых Review и все резервные копии.
- Рабочие SQLite, WAL/SHM, GETTEX-файлы, delivery observations, chart_cache и history64-evidence. Последние содержат используемые исходные подтверждения.
- Среда запуска, рабочий байткод программы, логотипы и .argosmodel: модели перевода загружаются непосредственно из этих архивов.
- Work2 и Store 0.15.

Work1 не закрывал и не перезапускал TEST ради очистки. Параллельные изменения V1 в real_portfolio.py и real_portfolio_view.py обнаружены и сохранены; очистка этих файлов не касалась. Другой чат выполнил свой согласованный перезапуск — это отдельный этап.

## Проверка и восстановление

1. Каждый из **13 414 payload-файлов** старых Review до удаления сравнен SHA256 с распакованным содержимым сохранённого ZIP: расхождений нет. Настоящие installed-manifest.json и пять старых тестовых баз дополнительно сохранены в небольшом ZIP с проверкой чтения и контрольных сумм.
2. Пробное восстановление отдельного файла из каждого из пяти пакетов: **5/5 PASS**. Пробные файлы удалены.
3. Перед удалением проверено отсутствие процессов старых Review 1–5. Удалялся только закрытый список с повторной проверкой размеров и SHA256; переходы через ссылки и выход за папку СМ запрещены.
4. После удаления Review 1–5 отсутствуют, Review 6/7 и основной установщик присутствуют. Защищённые файлы запуска, окружения и current.json совпали с исходными контрольными суммами. Итог missing-only проверки: **RESTORE_CHECK_PASS — 13 425 отсутствующих файлов, не относящихся к байткоду**. Эта проверка ничего не записывала.
5. После очистки 0.16-dev TEST ответил на лёгкую проверку Bridge; фоновый расчёт RUNNING. Это подтверждает связь, не торговую готовность всех акций. Старые торговые тесты и полный аудит повторно не запускались.

Частные списки и квитанции находятся в существующем «СМ-Архив»: SM storage inventory.json.gz, SM storage cleanup plan.json.gz, SM storage cleanup result.json.gz. Созданные при проверке текстовые списки сами сжаты с полным обратным сравнением: на 21 479 143 байта меньше их несжатых копий. Эта величина не добавлена к очистке исходной папки программы.

Там же сохранены SM storage cleanup rollback.zip и SM storage restore.py. По умолчанию скрипт лишь проверяет пакеты и недостающие файлы. Отдельный --restore восстанавливает только отсутствующие файлы; отличающиеся существующие файлы не перезаписывает, рабочую базу и указатель версии не заменяет. Старый тестовый байткод можно пересоздать из сохранённых исходников.
